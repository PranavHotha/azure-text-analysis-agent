PROJECT TECHNOLOGY STACK & ARCHITECTURE NOTES
================================================================================

1. Backend: FastAPI (Python 3.10+)
   - High-performance asynchronous REST API framework.
   - Hosts endpoints: /api/analyze, /api/chat, /api/status, /api/health.
   - Integrates with Azure AI Foundry SDK (AIProjectClient, Azure OpenAI).
   - Serves production React bundle build (text-agent-app/dist).

2. Frontend: React.js (Vite)
   - Client-side Single Page Application (SPA).
   - Document processing studio, live side-by-side redaction/NER views, chat assistant.
   - Local state management and monochrome minimalist UI design system.
   - Handles authentication state, token caching (cacheLocation="localstorage"), and attaching Bearer tokens to outgoing API requests.

3. Authentication (AuthN - "Who are you?"): OpenID Connect (OIDC) / Identity Provider
   - Handled via OpenID Connect (OIDC), the identity layer built on top of OAuth 2.0.
   - Implemented via Auth0 / Entra ID external tenant integration.
   - Issues signed JSON Web Tokens (ID tokens) containing user profile claims (name, email, subject ID).

4. Authorization (AuthZ - "What resources can you access?"): OAuth 2.0 & Microsoft Entra ID
   - OAuth 2.0 provides delegated access and Bearer access token protocol.
   - Microsoft Entra ID enforces tenant-level permissions and Role-Based Access Control (RBAC) (e.g. Cognitive Services User / Azure AI Developer).
   - Authorizes calls from backend credentials (MsalAzureCredential, DefaultAzureCredential) to Azure AI Foundry endpoints (ai.azure.com, cognitiveservices.azure.com).

================================================================================
KEYLESS MULTI-TENANT IMPLEMENTATION & RBAC RESOLUTION NOTES
================================================================================

1. Multi-Tenant Bring-Your-Own-Azure (MSAL OAuth 2.0 Migration)
   - Replaced static API keys and third-party Auth0 tokens with native Microsoft Authentication Library (@azure/msal-react, @azure/msal-browser).
   - Dynamic Tenant Authority: Allows users to input their Azure Directory (Tenant) ID in the sidebar, configuring the MSAL authority dynamically as https://login.microsoftonline.com/{tenantId}.
   - Personal Account Fix (AADSTS500207): Avoids the generic /common authority restriction by authenticating directly against the user's specific Azure tenant where their AI resources reside.
   - Target Scope: Requests delegated access with scope https://cognitiveservices.azure.com/user_impersonation, ensuring the Bearer token carries the legitimate audience for Azure AI Foundry and Cognitive Services.

2. Azure AI Foundry vs Azure OpenAI SDK Dynamic Routing
   - Azure AI Foundry Projects (*.services.ai.azure.com): Automatically routes through Azure AI Foundry SDK (AIProjectClient) using MsalAzureCredential, targeting /openai/v1/ and passing the specific Agent Name reference (extra_body={"agent_reference": {"name": agent_name}}).
   - Azure OpenAI Service (*.openai.azure.com): Automatically routes through OpenAI SDK (AzureOpenAI) using azure_ad_token_provider to supply the user's OAuth Bearer token.
   - Dynamic Selection: In server.py, get_azure_client detects the endpoint structure to pick the correct client architecture rather than forcing an incompatible endpoint path.

3. Real-Time Parameter Forwarding & Persistent UI State
   - Every request from the frontend to /api/chat and /api/analyze sends x-azure-endpoint, x-azure-model, and x-azure-agent-name headers, ensuring sidebar configurations take immediate effect.
   - Sidebar "Connect" button transitions to a sticky "Connected ✓" state upon confirmation, resetting back to "Connect" only when configuration fields are edited.

4. Azure RBAC Role Assignment Resolution
   - Root Cause of 500 / 401 / 403 Errors: When accessing Azure AI endpoints keylessly using an OAuth 2.0 Bearer token, Entra ID requires explicit data plane role permissions on the Azure resource.
   - Required Role: "Cognitive Services OpenAI User" (or "Cognitive Services OpenAI Contributor").
   - Configuration Steps:
     1. In Azure Portal, open the target Azure AI Foundry / Cognitive Services resource.
     2. Navigate to "Access Control (IAM)" in the left navigation menu.
     3. Click "Add" -> "Add role assignment".
     4. Select the role "Cognitive Services OpenAI User".
     5. Under "Members", assign access to the signed-in Microsoft account / principal.
     6. Save the assignment.
   - Result: Azure authorizes the user's Bearer token for chat completions and text analysis without needing an API key anywhere in the application.
